Solution journey

How the user moves through the proposed experience.
1 · RequestOne template on the portal; an Azure AI Foundry intake agent asks for anything missing.
2 · ValidateDeterministic Azure Policy-style rules, aligned to Defender for Cloud standards that also cover AWS. Pass or fail with the rule named.
3 · ApproveAgents draft the Terraform and risk memo; Entra-role approvers decide in Teams, in parallel.
4 · ExecuteCopilot-drafted PR behind a GitHub environment protection rule; AWS provisioning simulated.
5 · AuditEvery decision logged in Cosmos DB; handoffs and wait time land in a Fabric readiness dashboard.
Agents prepare evidence and explain blockers. They never approve or deploy.

EXECUTIVE SOLUTION MAP

Screenshot this section for the Statement of Work. Mastercard · LaunchGate · 12 Oct 2026

Customer evidence

Just to create a virtual machine takes 6 to 8 months. Around 12 handoffs. Ideal state is 1. Deployment is not enough, it includes policy and orchestration. Human review is important.
Maria, Business Development, Mastercard. Discovery, 12 Oct 2026. E

Core problem

Moving from an approved idea to a policy-compliant, development-ready cloud environment is a long, serial chain of manual handoffs in which compliance is re-proved by people every time.
One clear problem statement. Duration and handoff count as reported, not yet measured. E

Affected person

Mastercard engineers and business owners waiting to start building, and the security and compliance reviewers who repeat the same reviews.
Primary user: internal requester. Reviewer roles inferred from "guardrails". H

Proposed solution

LaunchGate: a policy-aware deployment control plane on the Microsoft cloud. One request; Azure AI Foundry agents prepare the evidence pack and draft the Terraform with GitHub Copilot; an Azure Policy-style gate decides; humans approve in Teams; GitHub enforces the gate; everything audited. Agents prepare, people authorize.
Prototype scope: one AWS dev-environment template, 8 rules citing public standards, three demo scenarios, simulated execution.

Expected impact

  • Handoffs: ~12 manual → 1 request + required approvals
  • Policy checks automated, repeatable, and portable to AWS via Defender for Cloud
  • Blockers visible in minutes, not weeks
  • Process survives staff turnover
Targets are hypotheses to validate. Prototype measures handoffs removed, violations caught, approvals enforced, audit completeness. H
Open questions to confirm with Mastercard or state as assumptions to EY:
  • Does "6 to 8 months" describe one environment request or the whole program readiness cycle?
  • Which teams own the 12 handoffs, and which are hard legal or regulatory gates?
  • How many environment requests per year? Cost of one month of delay?
  • Current tooling: ticketing, infrastructure as code, approval system?
  • Which policies could be encoded as rules today (region, encryption, logging, data class)?
  • Who at Mastercard would sponsor a pilot after the prototype?
